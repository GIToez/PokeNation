# Add an item

This tutorial adds a new item: a plain item (loot, quest item, evolution stone) or a usable
item with a script. The worked example is the **pokemon health potion** family
(server ids 12244-12247), which has all the parts: an `items.otb` entry, a client sprite, an
`items.xml` entry, an `actions.xml` binding, a Lua table and an NPC shop line.

All paths are relative to `server/` unless they start with `docs/`, `tools/` or `client/`.
`<NEW_ID>` is the new **server** id and `<NEW_CID>` its **client** id (section 5).

Items with their own PSoul systems have their own tutorials: [add-pokeball.md](add-pokeball.md),
[add-tm.md](add-tm.md), [add-held-item.md](add-held-item.md) (also vitamins). Evolution stones
are plain items plus an evolution entry ([add-evolution.md](add-evolution.md)).
To change an existing item see [edit-item.md](edit-item.md).

## 1. How an item works end to end

```
items.otb (binary)        server id 12244  ->  client id 11205, flags (stackable, pickupable, …)
client data.dat/.spr      client id 11205  ->  the sprite
items.xml                 <item id="12244" article="a" name="pokemon health potion"> + attributes
actions.xml               <action itemid="12244-12247" event="script" value="…/potions/healthPotions.lua"/>
healthPotions.lua         HEALTH_POTIONS[12244] = {healthGain = …, condition = health1, msg = "1", onlyPokemon = false, iconItemId = 11205}
npc/<Npc>.xml             shop_buyable "pokemon potion, 12244, 10;"
```

1. At startup the engine reads `items.otb`, then `items.xml` (`src/items.cpp`). The OTB
   defines which server ids exist and which client sprite each one uses. `items.xml` only adds
   names and attributes to ids that already exist.
2. When a player uses the item, the action registered for that id runs `onUse`
   (`events/actions/potions/healthPotions.lua:65-136`). It looks up `HEALTH_POTIONS[item.itemid]`
   and refuses with "Sorry, not possible." if the id is not in the table (line 66).
3. Whenever the server sends an item, it converts the server id to the client id from the
   OTB. PSoul's own `0xFF` packets do **not** convert; that is why the potion table holds
   `iconItemId = 11205`, the **client** id, for the status bar icon
   (`doPlayerSendPokemonStatusAdd`, line 128). See `docs/DEVELOPER_HANDBOOK.md` §7.1.

## 2. Files to edit

| # | File | Change | Needed for |
|---|------|--------|------------|
| 1 | `data/items/items.otb` (binary) | new entry `<NEW_ID>` → `<NEW_CID>` with the right flags | every new item |
| 2 | `client/data/things/data.dat` + `data.spr` | new object `<NEW_CID>` with its sprite | every new sprite ([add-client-asset.md](add-client-asset.md)) |
| 3 | `data/items/items.xml` | `<item id="<NEW_ID>" …>` | every new item |
| 4 | `data/actions/actions.xml` | `<action itemid="<NEW_ID>" event="script" value="…"/>` | usable items only |
| 5 | the action script (e.g. `lib/ps/events/actions/potions/healthPotions.lua`) | handle the new id | usable items only |
| 6 | `data/npc/<Npc>.xml` | `shop_buyable` / `shop_sellable` line | if an NPC trades it |
| 7 | loot: `data/monster/Pokemons/<species>.xml` `<loot>` | `<item id="<NEW_ID>" …/>` | if monsters drop it |

---

## 3. Files NOT to edit

* `data/items/items.xml` entries in the range 30001-30099. These ids are **fluid types**
  ("water", "blood", …, `items.xml:35807-…`). `src/items.cpp:520-527` maps them to ids 1-99,
  so they cannot hold a normal item.
* `data/lib/ps/tools/generateLoot.lua`: a generator; its output is not loaded.
* `docs/reference/*`: generated by `tools/gen_reference.py`.
* `original/` and the historical trees listed in `docs/DEVELOPER_HANDBOOK.md` §2.2.

## 4. Authoritative source paths

| What | Where |
|------|-------|
| Server id → client id, item flags | `data/items/items.otb` (loaded first, `src/items.cpp`) |
| Names and attributes | `data/items/items.xml`, parsed by `Items::parseItemNode` (`src/items.cpp:515-1755`) |
| `name`, `article`, `plural`, `sellprice` (XML attributes on `<item>`) | `items.cpp:533-544` |
| `<attribute key="description">`, `key="rareEffect"` (loot glow, `items.cpp:776-778`, used at `src/monster.cpp:1497`) and the standard TFS keys | `items.cpp:551-1751` |
| Use handlers | `data/actions/actions.xml` → `data/lib/ps/events/actions/…` |
| NPC sell price fallback | `shop_sellable` entries without a price use `sellprice` from `items.xml` (`data/npc/lib/npcsystem/modules.lua:940-944`, Lua `getItemSellPrice`, `src/luascript.cpp:13435-13447`) |

An `items.xml` entry for an id that is **not** in `items.otb` is not an error: `getItemType`
returns one shared dummy type (`src/items.cpp:1794-1805`) and the name is written there. The
next such entry then prints `[Warning - Items::loadFromXml] Duplicate registered item with id <id>`
(`items.cpp:531`), and the item cannot be created in game.

## 5. Required IDs and how to find free ones

| ID | Potion | Rule |
|----|--------|------|
| server id | 12244 | Must exist in `items.otb`. The highest server id in the OTB is **30135**, and every id up to it is either in `items.xml`, a fluid (30001-30099), or reserved by a formula (below). A new item therefore normally gets a **new OTB entry above 30135** |
| client id | 11205 | Sprite index in `data.dat`. The highest client id referenced by the OTB is 29130 |
| `iconItemId` (potions only) | 11205 | The client id, because it is sent raw in `0xFF` packets |

Look up the client id of an existing server id with the snippet in
[add-pokemon.md](add-pokemon.md) §5 (`12244 -> 11205`, `18083 -> 16688`).

List OTB ids that have no `items.xml` entry (read-only; uses the OTB parser of
`tools/check_references.py`):

```bash
cd /path/to/PokeNation      # repository root
python3 - <<'EOF'
import re, sys
sys.path.insert(0, "tools")
from check_references import parse_otb
otb = parse_otb("server/data/items/items.otb")
xml = open("server/data/items/items.xml", encoding="latin-1").read()
used = set()
for m in re.finditer(r'<item\s[^>]*>', xml):
    t = m.group(0)
    a = re.search(r'\bid="(\d+)"', t)
    if a: used.add(int(a.group(1)))
    f, to = re.search(r'fromid="(\d+)"', t), re.search(r'toid="(\d+)"', t)
    if f and to: used.update(range(int(f.group(1)), int(to.group(1)) + 1))
free = sorted(i for i in otb if i not in used and i >= 100 and not 30001 <= i <= 30099)
print(len(free), "OTB ids without items.xml entry; max OTB id", max(otb))
print(free[:30], "...", free[-30:])
EOF
```

These ids are **not automatically free**:

* `28149 + <N>` (`portrait`) and `28013 + <N>` (`dexPortrait`) are computed in code when a
  species uses `-1` (`config/pokemon.lua:32-39`). Most of the ids from 28265 upward in the list
  are such portraits.
* The map (`world/map.otbm`) can place any OTB id without an `items.xml` entry. Search the map
  in RME (`tools/rme/`) before taking one.
* Lua may create it by number. Check:

```bash
ID=30136
rg -n "\b$ID\b" server/data --glob '!**/_pokemon/**' --glob '!**/pokemon_backup/**' --glob '!**/moves_disabled/**' | head
rg -n "itemid=\"[^\"]*\b$ID\b" server/data/{actions,movements}/*.xml
```

Ranges such as `itemid="12244-12247"` are not matched by the last grep. Run
`python3 tools/check_references.py` and read the `xml.itemid` lines instead.

## 6. Related dependencies

* `items.otb` and the client `data.dat` must agree. The server only sends the client id; if
  the client has no object with that id, the item is invisible or shows another sprite.
* A potion's status bar icon (`iconItemId`) must be a client id that exists in `data.dat`.
* NPC shop lines are `name, id, price;`. The `id` must exist; `check_references.py` reports
  `npc.shop.itemid`. See [add-npc.md](add-npc.md) for the shop module.
* Players hold items by **server id** in the database (`player_items.itemtype`,
  `player_depotitems.itemtype`). Never renumber an item that players may own.

## 7. Example code

### 7.1 items.xml (real)

```18211:18213:server/data/items/items.xml
	<item id="12244" article="a" name="pokemon health potion">
		<attribute key="description" value="This potion increases your pokemon health regeneration for 1 minute. Power: 1." />
	</item>
```

A plain trade/loot item uses `sellprice`, as in `<item id="12253" article="a" name="pidgeot doll" sellprice="120" />`
(`items.xml:18232`). Rare loot adds `<attribute key="rareEffect" value="1" />`.

### 7.2 actions.xml (real)

```111:112:server/data/actions/actions.xml
	<!-- Potions -->
	<action itemid="12244-12247" event="script" value="../../lib/ps/events/actions/potions/healthPotions.lua" allowfaruse="1" />
```

`itemid` accepts a single id, a range `a-b`, or a `;`-separated list (`actions.xml:116`
`itemid="13653;13819"`). `allowfaruse="1"` lets the player use the item on a target that is
not adjacent (the potion script then checks a distance of 4 itself, line 73).

### 7.3 Lua table (real)

```29:34:server/data/lib/ps/events/actions/potions/healthPotions.lua
local HEALTH_POTIONS = {
    [12244] = {healthGain = math.floor(3000 / HEALTH_TICKS), condition = health1, msg = "1", onlyPokemon = false, iconItemId = 11205}, -- Pokemon Health Potion
    [12245] = {healthGain = math.floor(6000 / HEALTH_TICKS), condition = health2, msg = "2", onlyPokemon = true, iconItemId = 11206}, -- Great Pokemon Health Potion
    [12246] = {healthGain = math.floor(12000 / HEALTH_TICKS), condition = health3, msg = "3", onlyPokemon = true, iconItemId = 11207}, -- Ultra Pokemon Health Potion
    [12247] = {healthGain = math.floor(18000 / HEALTH_TICKS), condition = health4, msg = "4", onlyPokemon = true, iconItemId = 11208}, -- Super Pokemon Health Potion
}
```

`condition` must be a condition object created at the top of the same file (lines 5-27).

### 7.4 A new potion (template)

```xml
<!-- items.xml -->
<item id="<NEW_ID>" article="a" name="pokemon hyper health potion">
    <attribute key="description" value="This potion increases your pokemon health regeneration for 1 minute. Power: 5." />
</item>
<!-- actions.xml: a separate line, do not widen 12244-12247 into unrelated ids -->
<action itemid="<NEW_ID>" event="script" value="../../lib/ps/events/actions/potions/healthPotions.lua" allowfaruse="1" />
```

```lua
-- healthPotions.lua, next to health4
local health5 = createConditionObject(CONDITION_REGENERATION, HEALTH_DURATION * 1000, false,
    CONDITION_SUBID.REGENERATION.HEALTH_POTION)
setConditionParam(health5, CONDITION_PARAM_HEALTHGAIN, math.floor(24000 / HEALTH_TICKS))
setConditionParam(health5, CONDITION_PARAM_HEALTHTICKS, HEALTH_DELAY)
setConditionParam(health5, CONDITION_PARAM_LIGHT_LEVEL, true)
-- in HEALTH_POTIONS
    [<NEW_ID>] = {healthGain = math.floor(24000 / HEALTH_TICKS), condition = health5, msg = "5", onlyPokemon = true, iconItemId = <NEW_CID>},
```

### 7.5 NPC shop (real)

```13:14:server/data/npc/Alison.xml
		rope, 2120, 50;
		pokemon potion, 12244, 10;
```

## 8. Registration steps

1. Add the OTB entry (`<NEW_ID>` → `<NEW_CID>`) with an OTB item editor, and the sprite with an
   object builder (`docs/DEVELOPER_HANDBOOK.md` §7.1). The flags (stackable, pickupable,
   moveable, usable) come from the OTB/`data.dat` entry, not from `items.xml`.
2. Add the `items.xml` entry. Keep the file sorted by id; the engine does not require it, but
   the duplicate check is easier.
3. Usable items: add the `actions.xml` line and handle the id in the script.
4. Shops and loot: add the lines in the NPC XML and monster XML.
5. Restart.

---

## 9. Database requirements

None for a new item. Items the players own are rows in `player_items` / `player_depotitems`
with `itemtype = <server id>`; see [database-changes.md](database-changes.md) before touching them.

---

## 10. Client requirements

> The client is a frozen reference (`docs/LEGACY_CLIENT_REFERENCE.md`). Change client files
> only when the feature needs it (new sprites, the data-table lines listed here), and say why
> in the commit message. See [add-client-asset.md](add-client-asset.md).

* `data.dat` + `data.spr` must contain `<NEW_CID>`. Both are large files; `data.spr` is a Git
  LFS object (`docs/LARGE_FILES.md`).
* Look text, shop windows and loot messages get item names from the server. The only client
  name table is `ITEM_NAME_BY_ID` in `client/modules/gamelib/items.lua`, keyed by **client** id
  (e.g. `[16688] = "Fire Stone"`, line 754). It is read only by the market
  (`getItemNameByClientId`, `items.lua:966`, used at `game_market/market.lua:180,647`). Add a line
  there if the item should show its name in the market.
* Ship the new `data.dat`/`data.spr` to every player; an old client shows a wrong or missing
  sprite.

---

## 11. Server requirements

Restart. `/reload items` answers "Reloading items..." in game, but the server console prints
`[Notice - Game::reloadInfo] Reload type does not work.` (`src/game.cpp:6438-6441`) and nothing
is reloaded; `items.otb` and `items.xml` are only read at startup. `/reload actions` reloads the action
scripts, but not the item types. See `docs/DEVELOPER_HANDBOOK.md` §10.3.

## 12. Validation steps

```bash
tools/check_syntax.sh server/data/items       # items.xml well-formed
tools/check_syntax.sh server/data/actions
tools/check_syntax.sh server/data/lib/ps/events/actions/potions
python3 tools/check_references.py              # xml.itemid, xml.itemid.otbonly, xml.script, npc.shop.itemid
```

`check_syntax.sh` ends with `Lua: N files, 0 with syntax errors; XML: N files, 0 malformed`.

Startup log lines to look for:

* `[Warning - Items::loadFromXml] Duplicate registered item with id <id>`: the id has two
  `items.xml` entries, or it is not in `items.otb` (section 4).
* `[Warning - Items::loadFromXml] Unknown key value <key>`: misspelled `<attribute key>`
  (`items.cpp:1751`).
* `[Warning - Items::loadFromXml] Malformed entry (from: "…", to: "…")`: bad `fromid`/`toid`
  (`items.cpp:438`).
* `[Warning - Actions::registerEvent] Duplicate registered item id: <id>`
  (`src/actions.cpp:108,124`): the id is already bound to another action.
* `[Warning - Event::loadScript] Cannot load script (<path>)` followed by the Lua error
  (`src/baseevents.cpp:200`): wrong `value=` path or a syntax error.
* `[Warning] NpcSystem: Parameter(s) missing for item: …` (`npc/lib/npcsystem/modules.lua`):
  a broken shop line.

## 13. Test steps

Use GM Admin to create the item and Tester (or Trainer) to use it.

1. GM: `/i <NEW_ID>,1`. Without a count `/i` creates 100. The item goes into the hidden
   slot-3 backpack (BUG-12). Use `/i <NEW_ID>,1,true` to drop it on your tile instead
   (`talkactions/scripts/createitem.lua:25-30`). "Couldn't add item: <id>" means the player
   has no room; "Item wich such name does not exists." means a name lookup failed.
2. Look at it (Shift + click). Name and description must match `items.xml`.
3. Usable item: use it on your called Pokémon. For a potion expect the "HEAL +5" text, the
   status icon `<NEW_CID>` above the Pokémon bar, and after 60 s "The increased health
   regeneration of your Pokemon has ended." (`healthPotions.lua:44`). On yourself with
   `onlyPokemon = true`: "You can not use this potion on yourself."
4. Shop: say `hi`, `trade` to the NPC; the item must be listed with its price.
5. Loot: kill the monster with the new loot line and read the "Loot of a …" message.

## 14. Common mistakes

* Adding only an `items.xml` entry. Without an OTB entry the item does not exist (section 4).
* Using a client id where a server id is expected (`/i`, `actions.xml`, shops), or the
  reverse for `0xFF` icon fields such as `iconItemId`.
* Taking an id from 30001-30099 (fluids).
* Taking a "free" id from the snippet that is actually a computed portrait id (28149+N /
  28013+N) or is placed on the map.
* Widening an existing action range (`12244-12248`) into an id that already has an action;
  the second registration is rejected with the duplicate warning.
* Forgetting the Lua table entry: the action runs and answers "Sorry, not possible."

## 15. Failure symptoms

| Symptom | Cause |
|---------|-------|
| `/i <id>` creates nothing or an item without a name | Id not in `items.otb`, or no `items.xml` entry |
| Item is invisible or has another item's sprite | Client `data.dat` lacks `<NEW_CID>`, or the OTB maps to the wrong client id |
| "You cannot use this object." when using it (`src/player.cpp:1094`) | No `actions.xml` binding for the id |
| "Sorry, not possible." | The script has no table entry for the id (potions: `healthPotions.lua:66`), or the player is in a duel/arena/battle |
| `[Error - Action Interface]` + `…healthPotions.lua:onUse` + `attempt to index a nil value` | Table entry is missing a field (e.g. `condition`) |
| Status bar shows a wrong icon | `iconItemId` is a server id instead of a client id |
| NPC does not list the item | Shop line malformed or wrong id; see the NpcSystem warning |

## 16. Rollback advice

```bash
git checkout -- server/data/items/items.xml server/data/actions/actions.xml \
  server/data/lib/ps/events/actions/potions/healthPotions.lua server/data/npc/<Npc>.xml
git checkout -- server/data/items/items.otb      # binary; restores the old OTB
```

Restart afterwards; `/reload` cannot undo item types. If players already own the new item,
removing the OTB entry leaves rows in `player_items` with an unknown `itemtype`. Delete those
rows first (see [database-changes.md](database-changes.md)), or keep the OTB entry and only
remove the action.

- [ ] Test: `/i <NEW_ID>,1,true`, look text, use on a Pokémon, shop listing, loot
