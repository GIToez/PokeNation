# Add an achievement

Achievements are defined in one Lua file, granted by calling `doPlayerAchievementCheck`, stored
as rows in `player_achievements`, and shown in the quest log under the special quest
**"Achievements"** (id 15). The models are `FISH_1`/`FISH_2` (a statistic-driven series) and
`BOULDER_BADGE` (granted directly from Brock's `onWin`).

Paths are relative to `server/`.

---

## 1. The chain

```
lib/ps/systems/023-achievement.lua
   ACHIEVEMENT_IDS.X = <number>             (global table)
   ACHIEVEMENT_NAMES / DESCRIPTIONS / RANKS / CHECKS / SERIES / SECRET_ACHIEVEMENTS  (local tables)
        ▲
        │ doPlayerAchievementCheck(cid, ACHIEVEMENT_IDS.X [, var])   023-achievement.lua:1159-1182
        │   called from: onStatisticChange.lua, NPC scripts (setOnWin), quest onEnd, actions …
        ▼
MySQL  player_achievements (player_id, key)          psoul_extra_mysql.sql:78-83
        ▼
quest log "Achievements" (XML/quests.xml:539, holder="true")
   → creature event onQuestInfo (creaturescripts.xml:22) → onQuestInfo.lua:6-15 lists every id
```

## 5. Real examples

### 5.1 A series driven by a statistic (`023-achievement.lua:19-30`)

```lua
ACHIEVEMENT_IDS.FISH_1 = 1
ACHIEVEMENT_NAMES[ACHIEVEMENT_IDS.FISH_1] = "Hey! I fished something!"
ACHIEVEMENT_DESCRIPTIONS[ACHIEVEMENT_IDS.FISH_1] = "Fish 10 Pokemon."
ACHIEVEMENT_CHECKS[ACHIEVEMENT_IDS.FISH_1] = function(cid, var) return var >= 10 end
ACHIEVEMENT_RANKS[ACHIEVEMENT_IDS.FISH_1] = RANK_IDS.EASY

ACHIEVEMENT_IDS.FISH_2 = 2
ACHIEVEMENT_NAMES[ACHIEVEMENT_IDS.FISH_2] = "Oh yeah! More and more Pokemon in the sea!"
ACHIEVEMENT_DESCRIPTIONS[ACHIEVEMENT_IDS.FISH_2] = "Fish 100 Pokemon."
ACHIEVEMENT_CHECKS[ACHIEVEMENT_IDS.FISH_2] = function(cid, var) return var >= 100 end
ACHIEVEMENT_SERIES[ACHIEVEMENT_IDS.FISH_1] = ACHIEVEMENT_IDS.FISH_2
ACHIEVEMENT_RANKS[ACHIEVEMENT_IDS.FISH_2] = RANK_IDS.EASY
```

Triggered by `onStatisticChange.lua:2-3`:

```lua
    if (statisticId == PLAYER_STATISTIC_IDS.HOOKED_FISH) then
        doPlayerAchievementCheck(cid, ACHIEVEMENT_IDS.FISH_1, newValue)
```

Only the **first** member of a series is called. If the player already has `FISH_1`,
`doPlayerAchievementCheck` follows `ACHIEVEMENT_SERIES[FISH_1]` to `FISH_2` (`1160-1163`), and
so on.

### 5.2 A one-off granted from a script (`023-achievement.lua:781-784`)

```lua
ACHIEVEMENT_IDS.BOULDER_BADGE = 119
ACHIEVEMENT_NAMES[ACHIEVEMENT_IDS.BOULDER_BADGE] = "I am the Rock!"
ACHIEVEMENT_DESCRIPTIONS[ACHIEVEMENT_IDS.BOULDER_BADGE] = "Acquire the Boulder Badge."
ACHIEVEMENT_RANKS[ACHIEVEMENT_IDS.BOULDER_BADGE] = RANK_IDS.HARD
```

No `CHECKS` entry, so the achievement is granted unconditionally when called
(`1165`: `not ACHIEVEMENT_CHECKS[achievId] or …`). It is called from
`npc/scripts/npcbattle_brock.lua:31`.

### 5.3 What each table does

| Table | Required | Consumed at | If missing |
|-------|----------|-------------|-----------|
| `ACHIEVEMENT_IDS.<KEY> = n` | yes | everywhere | calling code passes `nil`; nothing is inserted |
| `ACHIEVEMENT_NAMES[n]` | yes | `1169`, `1184-1189` | the message reads `You earned a new achievement: ''` (`popString` turns `nil` into `""`, `luascript.cpp:1144-1151`) |
| `ACHIEVEMENT_DESCRIPTIONS[n]` | yes | `1191-1193`, `onQuestInfo.lua:11` | empty line in the quest log |
| `ACHIEVEMENT_RANKS[n]` | **yes** | `1171-1173` | `SCORE_BY_RANKS[nil]` is `nil`. The row is already inserted and the "earned" message sent, then `string.format("…%s…", nil)` at line 1173 raises a Lua error. The player gets no score, and `EARN_ACHIEVEMENT` is not counted |
| `ACHIEVEMENT_CHECKS[n] = function(cid, var)` | optional | `1165` | granted on every call |
| `ACHIEVEMENT_SERIES[prev] = n` | optional | `1161-1162` | – |
| `SECRET_ACHIEVEMENTS[n] = true` | optional | `onQuestInfo.lua:9` | hidden from the log until earned |

## 6. Required IDs and how to find free ones

The ids are plain integers, and the database key is the id (`player_achievements.key`).

```bash
cd server/data/lib/ps/systems
grep -o 'ACHIEVEMENT_IDS\.[A-Z0-9_]* = [0-9]*' 023-achievement.lua | awk '{print $3}' | sort -n | tail -1   # → 182
grep -n 'ACHIEVEMENT_IDS.MY_KEY\b' 023-achievement.lua                                                   # key unused?
```

The last id is `HALLOWEEN_WON_SATOSHI = 182` (line 1144), so the next free id is **183**.
**Never reuse an id**. Players who earned the old achievement have a row with that key and
would instantly "own" the new one.

## 7. Related dependencies

* `player_achievements` table (`psoul_extra_mysql.sql:78-83`).
* `HIGHSCORE_IDS.ACHIEVEMENTS` and `doPlayerAddHighscoreValue` (`1171-1172`).
* `PLAYER_STATISTIC_IDS.EARN_ACHIEVEMENT` → `ACHIEVEMENT_IDS.ACHIEVEMENT_1` series
  (`onStatisticChange.lua:29-30`). Adding achievements changes how fast players reach those.
* `onQuestInfo` iterates `pairs(ACHIEVEMENT_IDS)` (`onQuestInfo.lua:8`), so the display order
  is the Lua hash order, not the id order.

## 8. Example

Append to `023-achievement.lua` after the `HALLOWEEN_WON_SATOSHI` block:

```lua
ACHIEVEMENT_IDS.FOREST_PATROL = 183
ACHIEVEMENT_NAMES[ACHIEVEMENT_IDS.FOREST_PATROL] = "Berry Guardian"
ACHIEVEMENT_DESCRIPTIONS[ACHIEVEMENT_IDS.FOREST_PATROL] = "Help Ranger Liam protect the forest berries."
ACHIEVEMENT_RANKS[ACHIEVEMENT_IDS.FOREST_PATROL] = RANK_IDS.EASY
```

Grant it at the end of the quest from `add-quest.md` §8 (`onEnd` is called after the reward,
`002-quest.lua:362-364`):

```lua
            onEnd = function(cid) doPlayerAchievementCheck(cid, ACHIEVEMENT_IDS.FOREST_PATROL) end,
```

`023-achievement.lua` is loaded by `dodirectory(systems/)` (`lib/999-ps.lua:40`). The quest
config is `dofile`d by `002-quest.lua:82`. `002` sorts before `023`, but `onEnd` runs later at
runtime, so `ACHIEVEMENT_IDS.FOREST_PATROL` is defined by then. **Do not** read
`ACHIEVEMENT_IDS.*` at the top level of a file that loads before `023-achievement.lua`; there it
would still be `nil`.

## 9. Registration steps

1. Pick the id (§6) and add the four required lines (ID, NAME, DESCRIPTION, RANK).
2. Add the optional CHECK/SERIES/SECRET lines.
3. Call `doPlayerAchievementCheck` from the triggering script. For a statistic, add a branch
   to `onStatisticChange.lua` that calls the **first** id of the series with `newValue`.
4. Add `pt_br.loc` lines for the name and the description.

## 10. Database requirements

None beyond the existing table. Granting is an `INSERT INTO player_achievements (player_id, key)`
(`1166-1167`). If the table is missing, the console shows the SQL error and the log gets
`doPlayerAchievementCheck - Can't query.` (`1177-1178`). Fix it by importing the schema
(`database-changes.md`), not by creating the table by hand.

## 11. Client requirements

None. The quest-log window (`client/modules/game_questlog`) shows the text the server sends.

## 12. Server requirements

The tables live in `data/lib/`, which is loaded separately into every Lua state. Reload the
states that call your achievement (`/reload npcs` for NPC scripts, `/reload creaturescripts`
for `onStatisticChange`/`onQuestInfo`), or restart. Restart for `pt_br.loc`.

## 14. Test steps

There is no GM command that grants an achievement. Trigger the real path.

1. As Tester, finish the triggering action (here: the Ranger Liam quest, `add-quest.md` §14).
2. Expected messages:
   * `You earned a new achievement: 'Berry Guardian'` (`MESSAGE_EVENT_ADVANCE`), with red fireworks;
   * `You received 10 achievement score points.` (EASY).
3. Open the quest log → **Achievements** → "Berry Guardian (complete)" with its description.
4. Trigger again. Nothing happens (`getPlayerAchievement` is true and there is no series).
5. Check the database:

   ```sql
   SELECT * FROM player_achievements WHERE `key` = 183;
   ```

6. Reset for a re-test (server running is fine; the row is read live on every check):

   ```sql
   DELETE FROM player_achievements WHERE `key` = 183 AND player_id = (SELECT id FROM players WHERE name = 'Tester');
   ```

## 15. Common mistakes

* Forgetting `ACHIEVEMENT_RANKS` (see §5.3). This is the most damaging omission.
* Copy-pasting a block and leaving the old key on one line, e.g.
  `ACHIEVEMENT_NAMES[ACHIEVEMENT_IDS.HALLOWEEN_WON_SATOSHI] = "Berry Guardian"`. That
  overwrites the other achievement's name.
* Calling the second member of a series directly. `SERIES` only walks forward from the id
  you pass.
* Passing `var` to an achievement whose check does not use it, or forgetting `var` for one
  whose check does: `var >= 10` with `var = nil` raises "attempt to compare nil with number".
* Reusing a retired id.

## 16. Failure symptoms

| Symptom | Cause |
|---------|-------|
| `You earned a new achievement: ''` | `ACHIEVEMENT_NAMES` entry missing |
| "earned" message, then an `[Error - … Interface]` mentioning `bad argument #2 to 'format'` | `ACHIEVEMENT_RANKS` missing |
| Nothing at all | id is `nil` (typo in the `ACHIEVEMENT_IDS.KEY`), the check returns false, or the player already has it |
| `doPlayerAchievementCheck - Can't query.` in `server/logs/Error - <date>.log` | DB error (table missing, connection lost) |
| Achievement missing from the log but granted | `SECRET_ACHIEVEMENTS` and not yet earned, or the creature-script state was not reloaded |

## 17. Rollback advice

* `git revert` the definition and the trigger.
* Rows already inserted stay. They are invisible once the id is gone from `ACHIEVEMENT_IDS`
  (the log only lists ids in that table), but the highscore points remain. Remove both
  only if necessary, with a reviewed SQL file (`database-changes.md`). The highscore table
  is maintained by `doPlayerAddHighscoreValue`; inspect it before deleting anything.
* Never reuse the id after rollback.
